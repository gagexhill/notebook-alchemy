# Operations

Maintainer runbook: how to validate, scan, release and regenerate assets. User documentation is in
`README.md`; rules for changes are in `AGENTS.md`.

## Where Things Are

| Surface | Purpose | Source of truth |
|---|---|---|
| Open work | Bugs, features, releases | GitHub issues |
| Completed decisions | Design decisions and their rationale | `DEVLOG.md` |
| Rules for changes | Invariants, validation commands | `AGENTS.md` |
| Runtime defaults | Model, concurrency, paths | `src/notebook_alchemy/config.py`, `.env.example` |
| Model prices | Cost estimates in `dry-run` | `src/notebook_alchemy/claude.py` (`PRICING_USD_PER_M`) |
| Dependency updates | Weekly pip and Actions pull requests | `.github/dependabot.yml` |

## Validation

Local validation is the gate. Run from the repository root (`python` may be `py` on Windows).

```bash
python -m pip install -e ".[dev]"
python -m ruff check .
python -m ruff format --check .
python -m pytest
python -m notebook_alchemy.cli test
python -m pip_audit
```

`pip_audit` reports known vulnerabilities in installed dependencies.

## Hosted Execution

`.github/workflows/validate.yml` runs the same checks, a dependency audit and a secret scan on Linux and
Windows, and needs no secrets. It starts on every pull request to `main` and every push to `main`, so
those steps spend hosted runner time.

Hosted runs are not authorized by default. Local validation is the gate; a run happens only after the
maintainer approves it for that pull request. The approval is recorded in the pull request description
("Hosted run approved by the maintainer"), so the record lives with the run it covers. A workflow file,
an included runner allowance, or an earlier approved run is not permission for the next one. Dependabot
pull requests start a run too; review them in a batch rather than one at a time.

## Claude API Key

The maintainer's runs use a key that belongs to a Console service account (not a person), scoped to
one workspace kept for this tool. That workspace has:

- a monthly spend limit with an email alert below it;
- rate limits that allow only the model in `config.py` (every other model at 0 requests a minute), so
  a leaked key cannot be spent on costlier models;
- keys that expire after 30 days.

Rotate before the key expires, or at once if it may have leaked:

1. In the Console, create a key for the same service account, scoped to the same workspace.
2. Put it in `.env` as `ANTHROPIC_API_KEY` (never in a file git tracks), and run
   `notebook-alchemy status`.
3. Run one small build (`notebook-alchemy run <channel> --limit 1 --save books`) to confirm it works.
4. Delete the old key in the Console.

A key that may have leaked is disabled first, then rotated; the spend limit bounds what it could cost
in the meantime. Price changes go in `PRICING_USD_PER_M` with the date they were read.

## Secret Scan Hook

```bash
git config core.hooksPath .githooks
```

`pre-push` scans the commits being pushed with [gitleaks](https://github.com/gitleaks/gitleaks#installing)
(Homebrew, winget, Scoop or a release binary). Allowlist a known-public value narrowly in `.gitleaks.toml`.
A bypass is `GITLEAKS_BYPASS=1` with `HOOK_BYPASS_REASON`, and is recorded in the git directory.

## Release Assets

The recordings and images are generated by repeatable scripts, so nothing is drawn by hand. The icon is
the one exception: `docs/brand/icon.svg` is hand-written, and every favicon and app icon is rendered
from it.

```bash
python scripts/social_preview.py   # docs/images/social-preview.png (1280x640)
python scripts/render_demo.py docs/images/dry-run.svg "notebook-alchemy dry-run" -- dry-run <channel-url>
python scripts/brand_icons.py      # docs/brand/icons/ from docs/brand/icon.svg
```

`brand_icons.py` writes `favicon.svg`, `favicon.ico` (16, 32, 48), PNGs at 16, 32, 48, 180
(`apple-touch-icon.png`, on white), 192 and 512, a maskable 512 on white, and `notebook-alchemy.ico`
(16 to 256) for the Windows desktop shortcut. It needs Playwright's Chromium
(`python -m playwright install chromium`) and nothing else. Change the SVG, rerun the script and commit
both. `docs/brand/concepts/index.html` keeps the variants that were considered.

`render_demo.py` runs the command for real and records the terminal with Rich's SVG export. Record from a
neutral folder with a neutral notebook name, and check the SVG for local paths and account names before
committing it. The social preview is uploaded under Settings, General, Social preview.

## Installers

`install/install.ps1` and `install/install.sh` are what the README's one-line install downloads from
`main`, so a merge to `main` changes them for everyone. At the top of each script, one variable names
the package source (the `main` source archive; it becomes `notebook-alchemy` once the package is on
PyPI) and one names the folder the shortcut icon is downloaded from (`docs/brand/icons` on `main`).

They are not covered by `pytest`. After changing one, check it with shellcheck and run it against
scratch folders so your own install is untouched:

```bash
uvx --from shellcheck-py shellcheck -s sh -S style install/install.sh
```

Set `UV_INSTALL_DIR`, `UV_TOOL_DIR`, `UV_TOOL_BIN_DIR`, `UV_PYTHON_INSTALL_DIR`, `UV_CACHE_DIR`,
`PLAYWRIGHT_BROWSERS_PATH`, `ALCHEMY_INSTALL_WORK_DIR` and `ALCHEMY_INSTALL_SHORTCUT_DIR` to scratch
folders, plus `UV_NO_MODIFY_PATH=1` so your PATH is not changed, and on Windows `LOCALAPPDATA` for the
icon. `ALCHEMY_INSTALL_SOURCE` and `ALCHEMY_INSTALL_ICON_BASE` point a run at a branch. Run it twice:
the second run must update in place. Real Linux and macOS runs are tracked in a GitHub issue.

## Release

Tracked in a GitHub issue. A release names its source commit, built version, package digest, published
artifact and installed result, with unrun gates left open.
